# Change: Restructure document storage for audit-navigable, team-scoped paths

## Why

Business documents (quotations, POs, goods receive, completion reports, evaluations, P&L, acceptance reports) are stored under media-id-keyed folders (`storage/app/supplierquote/3/…`) mixed with Filament staging directories (`supplier-quotes/quotation/`) and orphaned files (`attachments/1/`, `public/1/`). Looking at the directory alone, nothing reveals which team owns a file, which deal it belongs to, or what the document is — an auditor walking a transaction cannot trace its document chain without database access. Three harder problems ride along: the document download **and delete** routes authorize with bare `auth()->check()` (`BuyerQuotePoDownloadController.php:33`, inline delete closures at `routes/web.php:95`, `:142`, and `:172` — the goods-receive one additionally always-404s because it compares `model_type` against the class name while the enforced morph map stores `'request'`); `AcceptanceReport` has no `team_id`, no morph alias (so its attachment uploads **silently fail today** with a swallowed `ClassMorphViolationException`), and no path-generator registration; and most inline `addMedia()` call sites bypass the traversal guard in `AttachUploadedFiles`. The media table holds 7 rows today (6 local documents + 1 public image) — this restructure will never be cheaper.

## What Changes

- **DS-1 Audit-navigable path structure (v3)**: all private business documents store under `documents/team-{team_id}/{year}/{request_number}/{document-type}[/{document-number}]/{media_id}/{filename}` — e.g. `documents/team-1/2026/REQ-2026-0001/supplier-quotes/SQ-2026-0003/12/quotation.pdf`. Business numbers containing `/` (e.g. `001-DS/QE/VII/2026`) are sanitized to path-safe slugs. Public media (product images, branding, avatars) is unaffected.
- **DS-2 Paths stamped at attach time, not derived at read time**: `AttachUploadedFiles` computes the full prefix once via a new `DocumentPathResolver` and stores it as a `path_prefix` custom property (alongside `path_version = 3`). `DocumentPathGenerator` reads the stamped prefix; v1/v2 media resolve exactly as before. No per-read DB joins, no path breakage when models are renumbered or deleted.
- **DS-3 Unified staging + one attach path**: every Filament `FileUpload->directory()` moves to `uploads-tmp/{feature}` via class constants (killing duplicated hardcoded strings and the shared `documents-temp` grab-bag), and **every** business-document attach converges on `AttachUploadedFiles` — the full inventory is ten inline `addMedia()` sites, not just the four `documents-temp` ones: `ViewQuotationEvaluation:146`, `SupplierOrderApprovalResource:160`, `ViewSupplierOrderApproval` (documents-temp), `ViewProfitAndLoss:146`, `AcceptanceReportResource:157`, `RequestResource/RelationManagers/BuyerQuotesRelationManager:1076`, `SupplierQuotesRelationManager:1657`, `GoodsReceiveRelationManager:192`, `CompletionReportsRelationManager:182,206`, and `Console/Commands/SeedRequestDocumentsCommand:226`. Without converging the staff relation managers and the seeder, the highest-traffic flows would keep minting v2 paths forever.
- **DS-4 Team-scoped authorization on document routes**: the two download controllers and the **three** inline delete closures (buyer PO, supplier quotation, goods receive — promoted to invokable controllers) verify the current user belongs to the owning record's team before serving or deleting; the goods-receive closure's broken morph-type comparison is fixed in the process.
- **DS-5 Acceptance report team scoping + media enablement** (prerequisite for DS-1): `acceptance_reports` gains `team_id` (backfilled from the parent request), the model gains `HasTeam` and an `acceptance_report` morph alias — which also repairs the currently silently-failing attachment uploads — plus `->useDisk('local')` on its media collection and registration in `config/media-library.php` `custom_path_generators`. Report numbering becomes team+year-scoped with `MAX(seq)` semantics and the unique index moves from `(request_id, report_number)` to `(team_id, report_number)`.
- **DS-6 Legacy migration + orphan hygiene**: an idempotent artisan command re-stamps and moves existing v2 local-disk documents (counted from the DB at run time, currently 6) into the v3 layout; a disk-aware orphan-scan command builds the referenced set from each media row's generator-resolved path per disk (id-folder presence is not enough — orphan `public/1/` collides with live local media id 1) and reports (with `--delete`, removes) unreferenced files.

## Known limitation (explicitly out of scope)

Document *listing* blades for several types (`document-list.blade.php`, `goods-receive-document-list.blade.php`, `CompletionReportsRelationManager`, `CreditLimitAcceptanceResource`) render `$media->getUrl()`, which for local-disk media produces a `/storage/…` URL that 404s — those document types have no working preview/download today and this change does not add routes for them (no regression: the physical move changes nothing user-visible there). A follow-up change should introduce a generic authorized document-download route to replace `getUrl()` on private media.

## Impact

- Affected specs: `document-storage` (NEW capability: layout, stamping, staging, authorization, hygiene), `erp-trading-core` (ADDED: acceptance report team scoping + attachment repair)
- Affected code: `app/Support/Media/DocumentPathGenerator.php` (v3 branch), new `app/Support/Media/DocumentPathResolver.php`, `app/Actions/Media/AttachUploadedFiles.php` (stamping), `config/media-library.php` (AcceptanceReport registration), ~12 `FileUpload` call sites (staging constants), 10 inline `addMedia()` sites rerouted, `app/Http/Controllers/*{Download,Delete}Controller.php` + `routes/web.php` (3 closures promoted), `app/Models/AcceptanceReport.php` + migration + `app/Providers/AppServiceProvider.php` (morph map), `app/Console/Commands/SeedRequestDocumentsCommand.php`, new artisan commands `documents:migrate-v3` / `documents:scan-orphans`
- Tests: new coverage for path resolution/stamping, authorization (cross-team 404 on all five routes), acceptance-report tenancy + attachment persistence; existing upload/download and seeder suites must stay green (seeder test may pin v2 stamping — update it)
- Risk notes: path generator changes must never alter resolution for existing v1/v2 media (pinned by tests before v3 lands); `AcceptanceReport` numbering rescope applies to new records only — existing numbers are immutable
